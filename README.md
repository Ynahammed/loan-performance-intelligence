# Loan Performance Intelligence Engine

**Intain Campus FinTech Challenge 2026 — AI Track**

Takes a monthly loan-level panel and tells a reviewer which records are
wrong, which loans are deteriorating, what the portfolio looks like under
stress, and why the model thinks so.

**[▶ Open the live dashboard](https://loan-performance-intelligence-8w9vjh7agyhxpnagceqnwo.streamlit.app)** — 9 pages, real scored output, no setup required.

`176 tests` · `5 prediction targets` · `12 generated reports` · `runs with no API key`

> **Synthetic data.** The pack in `data/` was generated by
> `generate_synthetic_data.py` to match the challenge specification.
> Nothing here describes real borrowers or real portfolio behaviour.

---

## The headline result

The transition engine's 12-month cumulative default probability, scored
against `next_12m_default_flag` — **a label that model never sees**:

|  | value |
|---|---|
| ROC-AUC | **0.846** |
| Predicted default rate | 1.21% |
| Observed default rate | 0.99% |
| Rows | 6,693 |

Two independently constructed estimators — a Markov chain over the
delinquency ladder, and a supervised classifier — agreeing on the same
quantity. That agreement is the strongest evidence in the project that
the modelling is sound.

**No layer can invent what the layer below did not produce.** The LLM
sees computed results, never a dataframe. The dashboard reads artifacts
and trains nothing. The anomaly detector never sees the exception labels,
so when it agrees with the rule engine that agreement is evidence rather
than circularity.

## Quick start

```bash
pip install -r requirements.txt

python -m scripts.run_data_intelligence     # profiling, rules, drift
python -m scripts.run_transition_engine     # survival + scenarios
python -m scripts.run_supervised_models     # 5 prediction targets
python -m scripts.run_anomaly_detection     # anomaly + exceptions
python -m scripts.run_explainability        # SHAP, errors, uncertainty
python -m scripts.run_llm_review            # copilot + governance
python -m scripts.build_submission          # submission.csv
python -m scripts.build_scenario_report     # scenario deliverable
python -m scripts.build_model_card          # model card

python -m streamlit run app/dashboard.py    # dashboard (or use the live link above)
python -m pytest                            # 176 tests
```

Roughly 10 minutes end to end. Commands use `python -m` because the
`streamlit` and `pytest` executables are not on `PATH` in every Python
installation.

**No API key needed.** A deterministic provider renders the same grounded
context objects, so the LLM layer works offline and a demo cannot fail on
an expired key. For a live provider, copy `.env.example` to `.env` and set
`LLM_PROVIDER=groq` plus `GROQ_API_KEY`; the model is discovered from the
API rather than hardcoded.

## What it answers

**Which records are wrong?**
A deterministic rule engine over `validation_rules.json` resolves **100%
of labelled exceptions at 98.2% precision**. Reconciliation against the
servicer feed finds orphan records, value conflicts and staleness —
source disagreement carries a **1.5× exception rate**, so it becomes a
model feature rather than a report finding.

**Which loans are deteriorating?**
Five targets. Every split is chronological with a **purge gap sized to
each label's forward horizon**, and rows whose outcome window runs past
the panel are dropped as immature.

**What happens under stress?**
A discrete-time multi-state hazard model over
`Current → 30 → 60 → 90 → Default`, with prepayment competing. Run
forward as a Markov chain it gives cumulative incidence curves; stressed
by macro multipliers it gives base / adverse-credit / high-prepayment
projections with segment breakdowns. **One engine for both.**

**Why does it think that?**
SHAP for what the model weighted, robust deviation from the population
for why a record looks unusual, and fold-to-fold spread for how much the
score depends on when the model was trained. A **single-loan what-if**
re-scores any loan through the same fitted pipeline when you change an
input.

## Models

| Job | Model | Baseline it was measured against |
|---|---|---|
| 4 binary targets | Histogram gradient boosting | Logistic regression, class-weighted |
| Next state | Hierarchical: *does it change?* → *to what?* | Persistence, and flat multiclass |
| Time-to-event | Per-origin multinomial logistic (discrete-time hazard), credibility-blended | Age-stratified empirical transition matrix |
| Competing risks | Aalen-Johansen, Kaplan-Meier, Cox PH (`lifelines`) | — |
| Anomaly | Isolation Forest, target-blind | — |
| Drift | Adversarial validation (gradient boosting) | PSI per feature |
| Calibration | Platt and isotonic, selected by policy | Uncalibrated scores |

Nothing exotic — all scikit-learn and lifelines. The work is in the
validation, not the algorithms. On 12-month default the **logistic
baseline won**, and it was kept.

## Results

| Target | Prevalence | PR-AUC | Lift | ROC-AUC | Recall @ 50% precision |
|---|---|---|---|---|---|
| 3-month delinquency | 5.66% | 0.411 | 7.3× | 0.701 | 0.392 |
| 6-month delinquency | 8.53% | 0.299 | 3.5× | 0.626 | 0.221 |
| 12-month default | 0.86% | 0.164 | **19.0×** | **0.860** | 0.158 |
| 12-month prepayment | 9.12% | 0.135 | 1.5× | 0.578 | **0.000** |

PR-AUC is the headline, not ROC-AUC: at these prevalences ROC-AUC is
dominated by the majority class and flatters everything.

**Next state** — the hierarchical model reaches log-loss **0.196**,
against 0.739 for a persistence baseline and 0.683 for flat multiclass,
at equal accuracy.

### Results that did not go our way

- **Prepayment is close to unpredictable out of time.** Recall at 50%
  precision is 0.000 — that queue cannot be operated on this data. The
  rate-incentive feature is strongly predictive *within* a period (6.3%
  → 30.2% across training-window quintiles) and collapses to 1.6× out of
  time as the rate environment shifts. The drift analysis had flagged
  `interest_rate` as the largest source of train/test separation before
  the model was trained.
- **Engineered features add nothing to 12-month default.** The logistic
  baseline ties the gradient-boosted model and is champion. With ~66
  events there is not enough signal to pay for the extra capacity.

Both appear in the model card as well. A limitations section nobody can
find is not a limitations section.

## Design notes

**Advisory, never decisive.** `recommended_action` emits only `REVIEW`,
`MONITOR` or `NO ACTION`. A test asserts no action can ever say deny,
foreclose, approve or terminate.

**Reports are generated from artifacts.** The model card and scenario
report are built from the JSON and CSV the pipelines write, so they
cannot drift from the numbers they describe.

**Guardrails on outputs, not instructions.** The LLM prompt says "do not
invent numbers", which makes fabrication unlikely. `src/llm/grounding.py`
makes it non-shippable — every number in a generation must trace back to
the context object it was given.

## Known limitations

- Dataset is synthetic and ~5× smaller than the specification suggests
  (47,883 rows against 250,000+). Rare events are thin: **49 Default
  transitions in the entire panel.**
- Metrics carry no confidence intervals. At these event counts the
  uncertainty around a PR-AUC is material and unquantified.
- Rule-engine recall is measured on the data the rules were written
  against, so 100% is closer to a fit than a forecast. What transfers is
  the mechanism, not the number.
- This pack contains **no cure transitions** out of 60/90DPD. Real
  servicing data has substantial cure rates, so the transition curves are
  optimistic about severity progression.
- No fairness analysis has been run, and `state` and `credit_score_band`
  are both used as features.
- Forward simulation evolves covariates mechanically only; borrower
  re-underwriting and servicing transfers are not modelled.
