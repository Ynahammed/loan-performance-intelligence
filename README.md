# Loan Performance Intelligence Engine

Built for the **Intain Campus FinTech Challenge 2026 — AI Track**.

An ML-first system for loan-level data. Machine learning does all the
predictive work — classification, discrete-time transition modelling,
calibration, anomaly detection, explainability. An LLM sits on top purely
as a narrator, and **never produces a number**: it receives computed
results as a validated context object and every generation is checked
against those results before anyone sees it.

> **Synthetic data.** The pack in `data/` was generated by
> `generate_synthetic_data.py` to match the shape of the challenge
> specification. Nothing in this repository describes real borrowers or
> real portfolio behaviour.

## Quick start

```bash
pip install -r requirements.txt

# Regenerate every artifact from the data pack (~10 minutes total)
python -m scripts.run_data_intelligence     # profiling, rules, drift
python -m scripts.run_transition_engine     # survival + scenarios
python -m scripts.run_supervised_models     # 5 prediction targets
python -m scripts.run_anomaly_detection     # anomaly + exceptions
python -m scripts.run_explainability        # SHAP, errors, uncertainty
python -m scripts.run_llm_review            # copilot + governance
python -m scripts.build_submission          # submission.csv
python -m scripts.build_scenario_report     # scenario deliverable
python -m scripts.build_model_card          # model card
python -m scripts.build_ai_development_log  # AI development log

streamlit run app/dashboard.py              # 9-page dashboard
pytest                                       # 176 tests
```

The LLM layer runs **with no API key configured** — a deterministic
provider renders the same grounded context objects, so the system is
fully functional offline and a demo cannot fail on an expired key. To use
a real provider, copy `.env.example` to `.env` and set `LLM_PROVIDER=groq`
plus `GROQ_API_KEY`. The model is discovered from the API rather than
hardcoded, because hosted catalogues change.

## What it does

Given a monthly loan panel, it answers four questions a reviewer actually
has, and shows its work for each.

**1. Which records are wrong?** A deterministic rule engine over
`validation_rules.json` resolves **100% of labelled exceptions at 98.2%
precision**. Reconciliation against the servicer feed finds orphan
records, value conflicts and staleness — and source disagreement carries
a **1.5× exception rate**, so it is carried forward as a model feature
rather than filed as a report finding.

**2. Which loans are deteriorating?** Five targets — delinquency at 3 and
6 months, default and prepayment at 12, and next month's state. Every
split is chronological with a **purge gap sized to each label's forward
horizon**, and rows whose outcome window runs past the panel are dropped
as immature.

**3. What happens under stress?** A discrete-time multi-state hazard
model over `Current → 30 → 60 → 90 → Default`, with prepayment competing.
Propagated forward as a Markov chain it gives cumulative incidence curves;
stressed by the macro multipliers it gives base / adverse-credit /
high-prepayment portfolio projections with segment breakdowns. Same engine
for both — there is no separate scenario model.

**4. Why does it think that?** SHAP for what the model weighted,
robust deviation from the population for why a record looks unusual, and
fold-to-fold spread for how stable the score is.

## Results

| Target | Prevalence | PR-AUC | Lift vs base rate | ROC-AUC | Recall @ 50% precision |
|---|---|---|---|---|---|
| 3-month delinquency | 5.66% | 0.411 | 7.3× | 0.701 | 0.392 |
| 6-month delinquency | 8.53% | 0.299 | 3.5× | 0.626 | 0.221 |
| 12-month default | 0.86% | 0.164 | 19.0× | 0.860 | 0.158 |
| 12-month prepayment | 9.12% | 0.135 | 1.5× | 0.578 | **0.000** |

PR-AUC is the headline rather than ROC-AUC: at these prevalences ROC-AUC
is dominated by the majority class and flatters everything.

**Next-state prediction**, hierarchical (does it change? → to what?):
log-loss **0.196** against 0.739 for a persistence baseline and 0.683 for
a flat multiclass model, at equal accuracy.

**The strongest evidence in the project** is a cross-check: the 12-month
cumulative default probability read off the transition chain, scored
against `next_12m_default_flag` — a label the chain never sees —
reaches **ROC-AUC 0.846**, predicting 1.21% against an observed 0.99%.
Two independently built estimators agreeing on the same quantity.

### Results that did not go our way

Both are reported here and in the model card rather than buried.

- **Prepayment is close to unpredictable out of time.** Recall at 50%
  precision is 0.000 — a precision-controlled prepayment queue cannot be
  operated on this data. The rate-incentive feature is strongly
  predictive *within* a period (6.3% → 30.2% across training-window
  quintiles) and the relationship collapses to 1.6× out of time as the
  rate environment shifts, which the drift analysis had flagged before
  the model was trained.
- **Engineered features add nothing to 12-month default.** The logistic
  baseline ties the gradient-boosted model and is champion. With ~66
  events there is not enough signal to pay for the extra capacity.

## Design principles

**Every layer produces something checkable, and no layer can invent what
the layer below did not produce.** The LLM never sees a dataframe, only
computed results, and a validator confirms every number it writes traces
back to them. The dashboard reads artifacts and trains nothing, so it
cannot display a figure no pipeline wrote. The anomaly detector never
sees the exception labels, so its agreement with the rule engine is
independent evidence rather than circularity.

**Advisory, never decisive.** `recommended_action` emits only `REVIEW`,
`MONITOR` or `NO ACTION`. A test asserts no action can ever say deny,
foreclose, approve or terminate.

**Documents are generated, not written.** The model card, scenario report
and AI development log are built from the artifacts, so they cannot drift
from the numbers they describe.

**Guardrails on outputs, not instructions.** The LLM prompt says "do not
invent numbers", which makes fabrication unlikely. `src/llm/grounding.py`
makes it non-shippable.

## Known limitations

Stated here as well as in the model card, because a limitations section
nobody reads is not a limitation section.

- The dataset is synthetic and ~5× smaller than the specification
  suggests (47,883 rows against 250,000+). Rare events are thin: 49
  Default transitions in the entire panel.
- Metrics carry no confidence intervals. At these event counts the
  uncertainty around a PR-AUC is material and unquantified.
- Rule-engine recall is measured on the data the rules were written
  against, so 100% is closer to a fit than a forecast. What transfers is
  the mechanism, not the number.
- This pack contains **no cure transitions** out of 60/90DPD. Real
  servicing data has substantial cure rates, so the transition curves are
  optimistic about severity progression.
- No fairness analysis has been run, and `state` and `credit_score_band`
  are both used as features.
- Forward simulation evolves covariates mechanically only; borrower
  re-underwriting and servicing transfers are not modelled.
