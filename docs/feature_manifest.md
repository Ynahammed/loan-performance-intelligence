# Feature Manifest

Generated by `src/features/engineering.py`. Every feature below is computed with an expanding window over a loan's own history up to and including the row being scored -- never beyond it.

## Amortisation

**`balance_ratio`** — Scale-free paydown progress, so a $90k and a $900k loan at the same point in their life look alike to the model.

    current_balance / original_balance

**`term_progress`** — Position in the loan's life on a 0-1 scale. Hazard is strongly age-dependent and this normalises across terms.

    loan_age / (loan_age + remaining_term)

**`amortisation_gap`** — Signed distance from the contractual schedule. Negative means paying ahead (a prepayment precursor); positive means behind or capitalised (a deterioration signal).

    balance_ratio - scheduled_balance_ratio(age, term, rate)

## Rate incentive

**`market_rate`** — Proxy for the prevailing rate a borrower could refinance into. Built only from loans already originated by that month, so it carries no lookahead.

    3-month rolling mean origination rate by calendar month

**`rate_incentive`** — The refinance motive. Positive means the borrower pays above market and has a reason to prepay. This is the feature the phase-1 model was missing when prepayment AUC came out at 0.50.

    interest_rate - market_rate

**`rate_incentive_pctile`** — Period-relative refinance motive. Uses only rows observed in the same month, so it introduces no lookahead, and it survives a shift in the rate environment that breaks the absolute version.

    percentile rank of rate_incentive within its reporting month

## Delinquency history

**`months_delinquent_to_date`** — Total delinquency exposure so far. Two loans that are Current today are not equally safe if one has missed six payments.

    expanding sum of (status in 30/60/90DPD), per loan

**`ever_delinquent`** — A blunt but powerful split: has this loan ever slipped at all.

    months_delinquent_to_date > 0

**`max_dpd_to_date`** — Worst point reached. A loan that touched 90DPD and cured carries different risk from one that never passed 30.

    expanding max of days_past_due, per loan

**`delinquency_streak`** — Distinguishes a one-month slip from a deepening roll. Roll rates out of 60DPD are far worse than out of a first 30DPD month.

    consecutive months in the current DPD episode

**`n_status_changes_to_date`** — Volatility of the servicing record. Loans that oscillate are both riskier and more likely to carry data defects.

    expanding count of month-over-month status changes, per loan

**`balance_change_3m`** — Short-run paydown velocity. A sudden flattening precedes delinquency; a sudden drop precedes prepayment.

    balance_ratio(t) - balance_ratio(t-3), per loan

**`ever_modified`** — A modification is a permanent change in the loan's character, not a one-month event.

    expanding max of modification_flag, per loan

## Band ordinals

**`credit_score_band_ordinal`** — Restores the ordering that one-hot encoding discards -- the model should know 620-659 sits below 660-699.

    midpoint lookup of the band label

**`ltv_band_ordinal`** — Restores the ordering that one-hot encoding discards -- the model should know 620-659 sits below 660-699.

    midpoint lookup of the band label

**`dti_band_ordinal`** — Restores the ordering that one-hot encoding discards -- the model should know 620-659 sits below 660-699.

    midpoint lookup of the band label

## Data quality

**`rule_violation_count`** — A record that fails logical checks is both more likely to be an exception and less trustworthy as model input.

    number of deterministic rules violated by this record

**`source_conflict`** — Servicer feed disagrees with the panel. Measured 1.5x exception lift.

    source_conflict

**`source_stale`** — The describing source updated long after (or impossibly before) the month.

    source_stale

**`servicer_update_lag_days`** — Continuous staleness, rather than only the thresholded flag.

    last_updated_at - reporting_month, in days

**`data_quality_score`** — Lets the model discount records it should trust less, instead of treating a defective row as equally informative.

    0-100 composite of completeness, outlyingness, rule and source penalties
