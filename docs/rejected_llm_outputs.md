# Rejected and Corrected LLM Output

Required evidence for Task 7. Generated by `scripts/run_llm_review.py`; every verdict below is produced by `src/llm/grounding.py` at run time.

## An honesty note about this document

No API credentials are configured for this run, so there is no real model output to show. Writing plausible text and captioning it "the LLM said this" would be fabricating evidence, which is the one thing this project refuses to do anywhere else.

So Section 1 uses a **fault-injection harness** (`FaultInjectionProvider`): text we wrote deliberately, containing the known failure modes, run through the real guardrail. It demonstrates that the control catches each class. It is labelled as fault injection in the audit log and here, and is never presented as something a model produced.

Section 2 carries rejections from live providers. It populates automatically from `logs/llm_calls.jsonl` whenever a key is configured, using the identical guardrail and the identical log.
