# Anomaly and Exception Report

Generated by `scripts/run_anomaly_detection.py`. Every figure is computed at run time.

Language note: this layer reports records as **unusual and requiring review**. It never asserts fraud or misconduct. An Isolation Forest observes that a record is statistically unlike its peers; it does not know why, and that distinction matters to whoever has to act on the flag.

The detector is target-blind: `exception_required`, `exception_type`, every performance target, and the rule outputs are all excluded from its feature set. Otherwise it would become a laundered copy of the rule engine, and its agreement with the rules would stop being evidence of anything.

## 3. Rule coverage and the residual

```
                    stage   n
total exceptions in panel 852
        resolved by rules 852
     rule false positives  16
   residual for the model   0
```

> Residual population: 47,015 rows carrying 0 exceptions (0.000% prevalence, against 1.779% before the rules ran).

> Only 0 exceptions survive the rules -- too few to train a residual model that could be evaluated honestly. The rule engine is reported as the complete solution for this target.

> Fewer than two learnable exception types survive the rules; type assignment is deterministic for every case the rules resolve, which is the great majority.

**A caveat that belongs next to that 100%.** These rules were written after inspecting this panel, so their measured recall is optimistic by construction -- it is closer to a fit than to a forecast. What transfers to the organizer's real pack is the *mechanism* (declare the invariant, measure precision and recall against the labels, promote a check into the engine when it beats a model), not the specific number. Every rule states the invariant it enforces, so each can be re-validated on new data in isolation.

The `balance_within_original` rule is the clearest example of that mechanism working. The residual model initially scored ROC-AUC 1.000 on the exceptions the declared rules missed. A perfect score on nine positives is not a discovery, it is a symptom: the month-over-month balance rule cannot fire on a loan's first observed row, because there is no previous row to compare. The profiler's cross-column check had already found the better invariant. Promoting it into the rule engine took balance_inconsistency recall from 94.3% to 100% and removed the need for the model entirely -- an auditable check in place of a classifier that was quietly rediscovering it.


`decided_by` travels with every record so a reviewer never has to guess whether they are looking at a rule citation or a model score. A rule that fires is a fact about the record and outranks any probability.
