# Model Card — Loan Performance Intelligence Engine

Generated by `scripts/build_model_card.py` from the artifacts in `models/`. Every metric is read from a snapshot written by the pipeline that produced it; none is transcribed by hand.

## 1. Objective

Predict loan performance on a monthly loan-level panel, and give a reviewer enough context to act: multi-horizon delinquency, default and prepayment probabilities, next-state prediction, a data-quality exception verdict, an anomaly score, and the drivers behind each.

Outputs are **advisory**. Nothing in this system decides a lending outcome; `recommended_action` in the submission emits only `REVIEW`, `MONITOR` or `NO ACTION`, and that constraint is enforced by a test rather than by convention.

## 5. Validation method

Every split is chronological. This is a panel where the same loan appears in many rows, so a random row split puts one loan's March and April rows on opposite sides and the model memorises rather than generalises — a condition the challenge rules list as disqualifying.

Splits additionally carry a **purge gap sized to each target's forward horizon**, because the labels look forward: without it, training rows carry labels determined by data inside the test period.

| Target | Horizon | Purge gap |
|---|---|---|
| 3-month delinquency | 3 months | 3 months |
| 6-month delinquency | 6 months | 6 months |
| 12-month default | 12 months | 12 months |
| 12-month prepayment | 12 months | 12 months |

Rows whose forward window extends past the end of the panel are dropped from both training and evaluation, since their labels could not have been observed.

## 7. Leakage controls

- **Target columns are excluded from every feature set.** `next_state` would predict `next_3m_delinquency_flag` almost perfectly and mean nothing.
- **`loss_severity_band` is dropped**, not imputed: it is 99.95% missing *and* a post-outcome field.
- **Identifiers and raw dates are excluded** so a tree cannot memorise individual loans or encode position in the panel.
- **History features use expanding windows within each loan**, never centred or ungrouped. A regression test truncates the future of a fixture whose tail is deliberately catastrophic and asserts the earlier rows are unchanged.
- **Purge gaps** prevent forward-looking labels straddling the split boundary; **label-maturity filtering** removes rows whose outcome window runs past the panel.
- **The anomaly detector is target-blind** — it never sees any target or the rule outputs, which is what makes its agreement with the rule engine independent evidence rather than a restatement.
- **Preprocessing is fitted inside the training fold only**, via sklearn Pipelines.

## 8. Known failure modes

These are measured, not anticipated. Each is reproducible from the artifact named.

**Prepayment is close to unpredictable out of time.** ROC-AUC 0.5779, and recall at 50% precision is 0.0 — meaning a precision-controlled prepayment review queue cannot be operated at all on this data. The `rate_incentive` feature is strongly predictive *within* a period (prepayment rises from 6.3% to 30.2% across training-window incentive quintiles) but the relationship does not transfer: the same spread collapses to 1.6x in the test window as the rate environment shifts. The drift analysis had flagged `interest_rate` as the single largest source of train/test separation before the model was trained. A period-relative version of the feature recovered only 0.561 to 0.575 ROC-AUC. *(`model_performance_report.md`, `data_intelligence_report.md`)*

**The delinquency models largely read current delinquency state.** At the 50%-precision operating point, false positives carry `days_past_due` of 12.4 against 0.13 for true negatives (+1.13 sd) — loans already delinquent that then cure. False negatives carry 0.0 against 45.8 for true positives (-2.75 sd) — clean loans taking a first slip. The model is strong on "already sliding keeps sliding" and close to blind on "clean loan, first miss", which is the case a reviewer most wants flagged. *(`explainability_report.md`)*

**Engineered features add nothing to 12-month default.** The logistic baseline and the gradient-boosted model tie, and the baseline is champion. With roughly 66 events in the evaluation window there is not enough signal to pay for the extra capacity. The target still has the best ROC-AUC and the highest lift of the four, but any conclusion drawn from it rests on very few events. *(`model_performance_report.md`)*

**Predictions are unstable across training periods.** Refitting on expanding time windows and scoring the same rows, the spread between fold models exceeds the prediction itself on 67.5% of rows. `model_confidence` in the submission reports this per record. *(`explainability_report.md`, `data/derived/uncertainty.csv`)*

**Rule-engine recall is measured on the data the rules were written against.** The engine resolves 100% of labelled exceptions at 98.2% precision, but the invariants were chosen after inspecting this panel, so that figure is closer to a fit than a forecast. What transfers to a different data pack is the mechanism — declare the invariant, measure precision and recall, promote a check when it beats a model — not the number. *(`anomaly_report.md`)*

**No cure transitions exist in this synthetic pack.** Zero observed transitions out of 60DPD or 90DPD back toward current. Real servicing data has substantial cure rates, so the transition matrix is optimistic about severity progression. The state machine is declared generally rather than narrowed to what was observed, so cures are representable if a real pack contains them. *(`survival_report.md`)*

## 9. Limitations

- The dataset is synthetic and roughly 5x smaller than the challenge specification suggests (47,883 rows against 250,000+). Rare-event targets are thin: 12-month default has 49 state transitions in the entire panel.
- Metrics carry no confidence intervals. At these event counts the uncertainty around a PR-AUC is material and is not quantified.
- Forward simulation holds credit band, LTV, state and servicer fixed, modelling only mechanical evolution (ageing, scheduled amortisation). Borrower re-underwriting and servicing transfers are not modelled.
- Scenario multipliers are applied as declared in `macro_scenarios.csv`. The engine propagates them faithfully; it does not validate that they are plausible.
- No fairness analysis has been run. State and credit band are used as features, and their disparate impact is unmeasured.

## 10. Reproducibility

Fixed seed (42) throughout. Each phase has one runner that regenerates its artifacts from the data pack:

```bash
python -m scripts.run_data_intelligence
python -m scripts.run_transition_engine
python -m scripts.run_supervised_models
python -m scripts.run_anomaly_detection
python -m scripts.run_explainability
python -m scripts.run_llm_review
python -m scripts.build_submission
python -m scripts.build_model_card
```

`pytest` covers the failure modes that do not announce themselves: leakage in history features, probability columns collapsing under calibration, guardrails silently weakening, rules leaking across loan boundaries.
